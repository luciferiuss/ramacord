# ИНСТРУКЦИЯ

Полное руководство по Ramacord: как поднять сервер, как всё устроено, что можно
трогать, что нельзя, и что делает каждая функция. Если нужна только установка на
сервер — сначала [docs/INSTALL.md](docs/INSTALL.md), если только админка —
[docs/ADMIN.md](docs/ADMIN.md).

---

## 1. Что это такое

Ramacord — чат с голосовыми каналами, который работает на вашем сервере. Один
процесс Node.js отдаёт и сайт, и API, и реальное время; голос идёт через
отдельный сервер LiveKit; данные лежат в SQLite рядом с кодом.

```
браузер ──HTTPS──► Caddy ──► Node.js (index.js) ──► mycord.db (SQLite)
   │                              │
   └──────── wss:// ─────────► LiveKit (голос, экран, камера)
```

- **Node.js** — Express 5, Socket.IO, загрузки, админ-логика, выдача токенов.
- **SQLite** (`mycord.db`) — аккаунты, сообщения, каналы, настройки, журнал.
- **LiveKit** — комнаты `voice-<id канала>`; без него чат работает, голос нет.
- **Caddy** (или Nginx) — HTTPS и проксирование; обязателен для микрофона.

Всё состояние — в двух местах: файл базы и папка `uploads/`. Больше ничего
хранить не нужно.

## 2. Быстрый запуск (локально, для пробы)

Нужен Node.js 22.13+ и, для голоса, `livekit-server`.

```bash
git clone https://github.com/luciferiuss/ramacord.git
cd ramacord
npm ci
npm run setup        # создаст .env и livekit.yaml со случайными ключами
```

В двух терминалах:

```bash
livekit-server --config ./livekit.yaml   # голосовой сервер
npm start                                # чат: http://127.0.0.1:3000
```

Откройте <http://127.0.0.1:3000>. Первый зарегистрированный аккаунт становится
администратором. `npm run setup` печатает код приглашения — он нужен при
регистрации. Все необязательные функции по умолчанию выключены: включите их в
админ-панели на вкладке «Функции».

Для пробы без настройки LiveKit: `livekit-server --dev` и в `.env` пара
`LIVEKIT_API_KEY=devkey`, `LIVEKIT_API_SECRET=secret`.

## 3. Установка на сервер (кратко)

Подробно, с юнитами systemd и Caddyfile — в [docs/INSTALL.md](docs/INSTALL.md).

1. Node.js 22, `git`, `caddy`, `livekit-server`.
2. Две A-записи: `chat.example.com` и `livekit.example.com`.
3. `npm ci`, `npm run setup`, затем правка `.env`:
   `NODE_ENV=production`, `HOST=127.0.0.1`, `LIVEKIT_URL=wss://livekit.example.com`,
   `ADMIN_NAME` (ваш ник), `INVITE_CODE` (12+ символов).
4. Открытые порты: `22/tcp`, `80/tcp`, `443/tcp`, `7881/tcp`, `50000-60000/udp`.
5. Перед Node.js — Caddy с HTTPS; наружу LiveKit только через `wss://`.
6. Запуск под systemd/PM2, чтобы «Перезапустить сервер» в админке работал.
7. Первый вход, включение функций, закрытие регистрации.

### Порядок первого запуска (важно)

1. Зарегистрируйте свой аккаунт **первым** — он станет администратором.
2. Впишите его ник в `ADMIN_NAME` и перезапустите сервис. Тогда роль не зависит
   от порядка регистрации.
3. Смените код приглашения в «Доступ» на свой (12+ символов).
4. Включите нужные функции на вкладке «Функции».
5. Когда все свои зарегистрировались — включите «Регистрация закрыта».
6. Настройте резервное копирование базы и `uploads/`.

## 4. Роли

| Роль | Как получить | Что может |
|---|---|---|
| Пользователь | регистрация по коду приглашения | чат, файлы, ЛС, голос (если включено) |
| Модератор | админ ставит галочку в «Аккаунтах» | вкладка «Аккаунты»: бан, мут, кик из голоса, перенос, сброс пароля; закрепление сообщений |
| Администратор | `ADMIN_NAME` или первый аккаунт | всё: каналы, пароли каналов, функции, доступ, сервер, бэкап, журнал, перезапуск |

Модератор не может трогать администратора, а другого модератора — только
администратор. Администратор не читает чужие личные сообщения: доступ к ЛС
только у двух участников.

---

## 5. Каналы

- **Текстовые** — обычные каналы с историей, файлами, поиском.
- **Голосовые** — комнаты LiveKit; текст в них не пишется.
- **Личные сообщения** — отдельный раздел, создаётся из профиля или «Участники»;
  доступ только у двоих, даже админ не читает.

Создание, переименование, порядок и пароль — у администратора в интерфейсе
(«Новый канал», перетаскивание, меню канала). Пароль канала — **от 8 символов**,
хранится в виде bcrypt-хеша. Кто ввёл пароль, получает доступ, пока админ не
сменит пароль. Смена пароля сбрасывает доступ у всех и выкидывает из канала.

Каналы `general`, `random`, `голосовой` создаются при первом запуске. Удалить
последний текстовый канал нельзя.

## 6. Функции чата

Всё, что помечено «флаг», включается администратором на вкладке «Функции» и
действует сразу у всех, без перезапуска. По умолчанию выключено всё, кроме
базового чата и входа.

| Функция | Что делает | Ограничения |
|---|---|---|
| Непрочитанные и упоминания | бейджи «N»/«@M», подсветка `@ник`, счётчик в заголовке | сбрасывается при открытии канала/фокусе окна |
| Ответ на сообщение | цитата над ответом, переход к оригиналу | цитата хранится вместе с сообщением |
| Редактирование | правка своих сообщений, пометка «(изменено)» | только свои, только 24 часа |
| Удаление | у автора остаётся «Сообщение удалено»; админ удаляет без следа | свои — 24 часа; админ — любое |
| Реакции | 8 эмодзи, счётчики | одна и та же реакция снимается повтором |
| Медиа | встроенные плееры видео/аудио, просмотр картинок | только если сервер отдал файл |
| Вставка файлов | Ctrl+V и перетаскивание с подтверждением | те же лимиты, что у загрузки |
| Кликабельные ссылки | `https?://` превращаются в ссылки | только http/https |
| Предпросмотр ссылок | карточка «сайт / заголовок / описание» | сервер сам открывает страницу: не чаще 10 раз в минуту, только публичные адреса, ответ до 300 КБ |
| Форматирование | `код`, **жирный**, *курсив*, ~~зачёркнутый~~, ```блок кода``` | без вложенных сложных конструкций |
| «Печатает…» | индикатор набора | не чаще раза в 2 секунды |
| Поиск по каналу | ищет по текущему каналу | от 2 символов, до 50 результатов |
| Закреплённые | список закреплённых сообщений | закреплять может админ/модератор; в ЛС нельзя |
| Уведомления | системные окна и звук | режим в настройках; «не беспокоить» подавляет |
| Личные сообщения | переписка двух человек | включается флагом `dm` |
| Статусы | «В сети», «Отошёл», «Не беспокоить», своя строка | строка до 60 символов |
| Профиль | «о себе» (до 200), дата регистрации, где в голосе | — |
| Очистка/удаление ЛС | стирает переписку сразу у обоих | необратимо |
| Улучшенный шумодав (`ns_pro`) | HPF, умные ворота, de-click, сила | см. раздел 8 |
| DeepFilterNet3 (`ns_dfn`) | нейросетевой шумодав | грузит ~17 МБ модель, нужен `ns_pro`-режим |

Сообщение — до 2000 символов. Ник — 2–24 символа: буквы, цифры, пробел, `_ . -`.
Пароль аккаунта — от 6 символов.

### Файлы

- До **25 МБ** за файл, не больше **30 файлов в час** с аккаунта.
- Дневные квоты: **250 МБ** на аккаунт и **2 ГБ** на сервер за 24 часа
  (меняются в `.env`, см. раздел 11).
- Имя на диске — UUID + расширение; раздаются с `X-Content-Type-Options: nosniff`,
  всё кроме картинок — как скачивание.
- Не прикреплённые к сообщениям файлы удаляются автоматически (раз в 6 часов,
  старше суток).
- Аватар — только JPEG до 1 МБ, клиент заранее сжимает до 256×256.

## 7. Голос

- Вход — клик по голосовому каналу. Микрофон включается сам; если браузер не дал
  доступ — вы подключены как слушатель.
- Кнопки: «Микрофон», «Звук» (локально не слышать никого), «Выйти из голоса»,
  «Показать экран», камера. В списке участников видны значки: заглушён
  администратором, микрофон выключен, звук выключен, личная заглушка.
- Правый клик по участнику: «Выключить звук» (только у себя) и «Громкость
  (только для вас)».
- **Токен голоса живёт 10 минут.** LiveKit сам продлевает его, пока вы в
  комнате, поэтому длинные звонки не рвутся. Короткий срок нужен, чтобы
  выгнанный человек не мог вернуться со сохранённым токеном: после кика, бана
  или смены пароля канала старый токен умирает максимум за 10 минут. Менять
  срок — только через `VOICE_TOKEN_TTL` (см. раздел 11).
- «Заглушить всех» на вкладке «Голос» глушит всех, кроме администратора, включая
  модераторов и тех, кто зайдёт позже.
- Модератор в меню участника: «Заглушить для всех» / «Снять заглушку»,
  «Выкинуть из голоса». Админ ещё «Перенести в «канал»» — перенос даёт человеку
  доступ к закрытому каналу.
- Кик из голоса — не бан: человек может зайти снова. Бан — в «Аккаунтах»:
  сбрасываются сессии, и войти он уже не сможет.

### Демонстрация экрана и камера

- «Показ экрана»: разрешение 720p / 1080p / 1440p / до 4K, частота 15 / 30 / 60.
  Битрейт подбирается автоматически: 720p — 1,5–4 Мбит/с, 1080p — 3–9,
  1440p — 5–14 (для 4K берётся тариф 1440p).
- В браузере источник выбирается системным окном; в десктопном приложении —
  своим списком «Экраны / Приложения» и тумблером звука компьютера.
- Камера: 720p, 30 кадров/с, ~1,5 Мбит/с; фронтальная зеркалится.
- Для показа экрана нужен исходящий канал: подсказка в настройках показывает
  примерную скорость.

### Клавиши

- «Говорить по клавише (рация)» и «Вкл/выкл микрофон» — назначаются в настройках.
- В браузере клавиши работают, только пока вкладка с чатом активна. В десктопном
  приложении — поверх других программ.
- Пока клавиша удерживается, звук идёт; после отпускания — 200 мс хвоста.

## 8. Шумоподавление и микрофон

Это самая тонкая часть. Настройки открываются шестерёнкой в панели голоса, пока
вы в голосовом канале. Они хранятся в браузере (`localStorage`), у каждого свои.

### Что есть

1. **«Шумоподавление»** — базовый RNNoise (WASM). По умолчанию выключен. При
   включении вместо сырого микрофона в звонок идёт очищенный звук. Если сервер не
   отдал модуль (`/vendor/ns-manifest.json`), кнопка покажет ошибку и вернётся в
   выключенное состояние — это не поломка чата.
2. **«Усиленное (DeepFilterNet3)»** — нейросетевой шумодав. Виден только если
   администратор включил функцию `ns_dfn`. При включении:
   - загружается модель (~17 МБ, первый раз долго; сервер должен отдавать сжатие);
   - автоматически включается и базовый шумодав;
   - при нехватке производительности (переполнение буфера ворклета) режим сам
     выключается с сообщением — это защита, а не баг;
   - если WASM не поддержан или модель не загрузилась — откат на RNNoise.
3. **«Сила шумоподавления»** (0–100 %, по умолчанию 50 %) — насколько сильно
   давить шум. В DeepFilterNet3 меняет глубину на лету, без перезапуска движка.
4. **«Громкость микрофона»** (0–200 %, по умолчанию 100 %) — усиление вашего
   сигнала.
5. **«Чувствительность»** (0–100, по умолчанию 0 = выключено) — порог микрофонного
   гейта: тише порога звук не проходит. 0 — гейт выключен; 100 — самый высокий
   порог (нужно говорить громко). Полоска уровня показывает, где сейчас порог.
6. **Улучшенный режим (`ns_pro`)** даёт: обрезку низов (~90 Гц), гистерезис
   открытия/закрытия, плавные атаку (6 мс) и спад (120 мс), удержание (180 мс),
   подавление щелчков и «пол» подавления −60 дБ × сила. В нём при первом
   включении шумодава чувствительность сама ставится на 20 %.

### Что происходит с браузерными настройками

- Эхоподавление (`echoCancellation`) включено всегда.
- Шумоподавление и автоусиление браузера (`noiseSuppression`, `autoGainControl`)
  выключаются **только** когда включён улучшенный режим и наш шумодав — чтобы не
  было двойной обработки. Применяется при входе в голосовой канал, не на лету.
- Выбора микрофона/динамика в интерфейсе нет: используется устройство по
  умолчанию из системы.

### Что можно и чего нельзя

**Можно:**
- включать/выключать шумодав в любой момент (кроме смены устройств);
- крутить силу и чувствительность на лету;
- держать DeepFilterNet3 включённым, если компьютер тянет: смотрите, чтобы не
  появлялось сообщений об автоматическом отключении;
- выключать шумодав, если он «съедает» голос — это нормальный выбор.

**Нельзя/не стоит:**
- включать DeepFilterNet3 на слабом ноутбуке или телефоне — получите задержку и
  автоотключение; начните с RNNoise;
- ставить силу 100 % и одновременно громкость 200 % — получите артефакты и
  «металлический» голос;
- включать шумодав браузера поверх нашего (это делает код сам, не мешайте
  настройками ОС);
- менять флаги `ns_pro`/`ns_dfn` «на глаз» без теста: `ns_dfn` без `ns_pro`
  работает, но сила и гейт ведут себя иначе;
- влезать в `const MIC_WORKLET` в `public/index.html` — на нём держится тест
  `npm test`, и это единственное место, где живёт DSP-гейт.

## 9. Админ-панель

Открывается кнопкой «Админ-панель» (у модератора — «Модерация»). Вкладки:

### Аккаунты (видит и модератор)

- Поиск по нику, состояние: в сети / не в сети / в голосе / заглушён /
  заблокирован.
- «Заблокировать» — сразу выкидывает из чата и голоса, вход запрещён, пока не
  разблокируют.
- Меню «⋯»: «Заглушить для всех», «Выкинуть из голоса», «Перенести в «канал»»,
  «Сделать модератором», «Сбросить пароль», «Удалить аккаунт».
- «Сбросить пароль» показывает временный пароль один раз, все сессии рвутся.
- «Удалить аккаунт» **необратимо**: сообщения остаются, личные переписки
  удаляются. Ник потом можно занять заново.

### Голос

- «Заглушить всех» / «Снять заглушку со всех». Действует на всех, кроме
  администратора, включая заходящих позже.

### Чаты

- «Удалить все чаты» — стирает сообщения и файлы во всех каналах, каналы
  остаются. **Необратимо.**
- «Очистить один канал» — то же для выбранного. **Необратимо.**
- «Автоочистка» — одноразовое удаление через 7 дней; до срока можно отменить.

### Доступ

- «Код приглашения» — «Сменить», **от 12 до 64 символов**; старый код перестаёт
  работать для новых регистраций.
- «Регистрация закрыта» — новые аккаунты нельзя создать даже с кодом.
- «Режим обслуживания» — все, кроме администратора, отключаются и не могут
  войти.

### Сервер

- Статистика: онлайн, в голосе, аккаунтов, сообщений, размер базы и файлов,
  время работы, PID, версия Node.
- Предупреждение, если `index.js`/`db.js` на диске новее запущенного процесса —
  значит, файлы обновили, а сервер не перезапустили. `public/index.html`
  перезапуск не требует, достаточно обновить страницу.
- «Резервная копия базы» — скачивает `mycord.db`. Внутри хеши паролей и токены
  входа: храните как пароль.
- «Неиспользуемые файлы» — удаляет загрузки, не прикреплённые к сообщениям.
  Файлы, загруженные за последние 15 минут, не трогает.
- «Объявление для всех» — окно у всех, кто сейчас онлайн (до 1000 символов).
- «Перезапустить сервер» — процесс завершается с кодом 1, менеджер процессов
  (systemd/PM2/Docker) поднимает его. Без менеджера сервер останется лежать.

### Журнал

Последние 200 действий (в базе хранится 1000): кто, что, когда. Только чтение.

### Функции

Список всех необязательных возможностей с тумблерами, по группам «Чат», «Личное
общение», «Голос». Включение действует сразу всем и пишется в журнал.

## 10. Что можно трогать, а что нельзя

### Можно (безопасно)

| Что | Как |
|---|---|
| Функции | админка → «Функции» |
| Каналы, их порядок и пароли | админка/интерфейс админа |
| Регистрация, код приглашения, обслуживание | «Доступ» |
| Аккаунты: бан, мут, модератор, сброс пароля | «Аккаунты» |
| Очистка чатов | «Чаты» (осторожно, необратимо) |
| Объявление, бэкап, перезапуск | «Сервер» |
| Настройки микрофона | у каждого свои, в панели голоса |
| Лимиты и адреса | `.env` + перезапуск сервиса |

### Нельзя (сломает данные или безопасность)

| Что | Почему |
|---|---|
| Удалять или пересоздавать `mycord.db`, `mycord.db-wal`, `mycord.db-shm` | это живые данные: аккаунты, сообщения, токены |
| Удалять `uploads/` | файлы и аватарки пользователей |
| Коммитить `.env`, `livekit.yaml`, `mycord.db`, `uploads/` | секреты и личные данные |
| Запускать прод с `devkey`/`secret` или без `INVITE_CODE` | голос и регистрация открыты всем |
| Ставить `HOST=0.0.0.0` без прокси с HTTPS | сервер открыт напрямую, микрофон не работает, IP подделывается |
| Менять имена socket-событий, поля payload, REST-роуты | без правки клиента всё развалится |
| Убирать bcrypt, лимиты входа и загрузок, `timingSafeEqual` | ослабление безопасности |
| Править `const MIC_WORKLET` и разметку теста | сломает `npm test` и DSP-гейт |
| Править `db.js` без миграции через `addColumn` | потеряете данные на живой базе |
| Отдавать `/uploads` через свой прокси с `Content-Type` от расширения | можно получить XSS; сервер уже ставит `nosniff` и скачивание |

## 11. Настройки сервера (.env)

Читаются при запуске (`npm start` читает `.env`). Переменная окружения имеет
приоритет над файлом. После правки — перезапуск сервиса.

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `PORT` | `3000` | порт HTTP |
| `HOST` | `127.0.0.1` | адрес прослушивания; снаружи — прокси |
| `NODE_ENV` | — | `production` включает проверки при старте |
| `ADMIN_NAME` | первый аккаунт | ник администратора |
| `INVITE_CODE` | пусто | код приглашения (12+ символов) |
| `LIVEKIT_URL` | `ws://localhost:7880` | адрес LiveKit, в проде `wss://` |
| `LIVEKIT_API_KEY` | `devkey` | ключ LiveKit |
| `LIVEKIT_API_SECRET` | `secret` | секрет LiveKit |
| `LIVEKIT_API_URL` | из `LIVEKIT_URL` | адрес управления LiveKit |
| `VOICE_TOKEN_TTL` | `10m` | срок токена голоса (10 минут) |
| `UPLOAD_PER_HOUR` | `30` | файлов в час с аккаунта |
| `UPLOAD_USER_MB` | `250` | мегабайт за сутки на аккаунт |
| `UPLOAD_TOTAL_MB` | `2048` | мегабайт за сутки на сервер |
| `REG_LIMIT_IP` | `3` | аккаунтов с одного IP за сутки |
| `REG_LIMIT_TOTAL` | `20` | аккаунтов на сервер за сутки |

С `NODE_ENV=production` сервер не стартует без `LIVEKIT_*` и `INVITE_CODE`, а
короткий код приглашения вызывает предупреждение в логе.

На лету (без перезапуска) меняются: функции, код приглашения, регистрация,
обслуживание, каналы, аккаунты. Требуют перезапуска: переменные окружения,
`ADMIN_NAME`, ключи LiveKit, лимиты.

## 12. Обслуживание

**Бэкап.** Админка → «Сервер» → «Резервная копия базы», либо на сервере:

```bash
sqlite3 /opt/ramacord/mycord.db ".backup '/var/backups/ramacord-$(date +%F).db'"
tar czf /var/backups/uploads-$(date +%F).tar.gz -C /opt/ramacord uploads
```

**Обновление.**

```bash
cd /opt/ramacord && git pull && npm ci && sudo systemctl restart ramacord
```

База и `uploads/` при обновлении не затрагиваются. Клиентские правки
(`public/index.html`) не требуют перезапуска — достаточно обновить страницу.

**Логи.** `journalctl -u ramacord -n 100` (systemd) или `pm2 logs`.

**Диск.** Следите за размером `uploads/` и квотами; при переполнении сервер
перестаёт принимать файлы (это защита), а SQLite может пострадать.

**Сессии.** Живут 30 дней, просроченные удаляются раз в час. Бан и сброс пароля
рвут сессии сразу.

## 13. Безопасность: что уже сделано

- Пароли — только bcrypt (cost 10), сравнение без утечки по времени.
- Сессии — случайные токены в базе на 30 дней, отзыв при выходе, бане, смене
  пароля.
- Регистрация: код приглашения (12+), лимит 3 аккаунта с IP и 20 на сервер в
  сутки, лимиты неудачных попыток входа.
- Загрузки: 25 МБ на файл, 30 в час, 250 МБ в сутки на аккаунт, 2 ГБ на сервер;
  имена UUID; не-картинки отдаются как скачивание.
- Каналы с паролем: bcrypt, пароль от 8 символов, лимит попыток ввода.
- Предпросмотр ссылок не ходит в localhost/приватные сети и в метаданные облака,
  проверяет адрес в момент соединения, ограничен по размеру и времени.
- Админ-действия проверяются на каждом событии и пишутся в журнал.
- Голос: токен 10 минут (LiveKit продлевает его в активном звонке), после кика,
  бана или смены пароля старый токен умирает максимум за 10 минут.
- Секретов в коде нет: всё в `.env`; в git он не попадает.

Чего нет и что стоит добавить при желании: CSP/строгие заголовки, раздача файлов
через проверку доступа (сейчас по UUID-ссылке), хранение авторства сообщений по
id пользователя, а не по нику. Это не дыры «снаружи», но лучше знать.

## 14. Частые проблемы

| Симптом | Причина и что делать |
|---|---|
| «Не заданы переменные окружения» | `.env` не найден/пуст; запускайте из папки проекта через `npm start` |
| 502 от Caddy | сервер не слушает: `journalctl -u ramacord -n 50` |
| Голос не подключается | `LIVEKIT_URL` без `wss://`, закрыты 7881/tcp и UDP-диапазон, `livekit.` домен не проксируется |
| Микрофон не спрашивается | страница по `http://` — нужен HTTPS |
| «Нет доступа к микрофону» | браузер запретил; вы слушатель, говорить не сможете |
| Долго включается DeepFilterNet3 | ~17 МБ WASM; включите `encode zstd gzip` в Caddy |
| Шумодав сам выключился | не хватает CPU: выключите DeepFilterNet3, оставьте RNNoise |
| «С этого адреса уже создано слишком много аккаунтов» | лимит регистраций; подождите сутки или поднимите `REG_LIMIT_IP` |
| «Дневной лимит загрузок» | квота аккаунта; подождите или поднимите `UPLOAD_USER_MB` |
| «Пароль канала: от 8 символов» | новый минимум пароля канала |
| «Код приглашения: от 12 до 64 символов» | новый минимум кода |
| Кнопка «Перезапустить сервер» не поднимает сервер | нет менеджера процессов: systemd/PM2/Docker с `on-failure` |
| После обновления старый интерфейс | Ctrl+F5: браузер закэшировал `index.html` |
