# AGENTS.md

Ramacord — чат с голосовыми каналами. Один npm-пакет: сервер и веб-клиент в
одном процессе. Интерфейс и комментарии — на русском.

## Стек и версии

- Node.js >= 22.13 (ESM, `"type": "module"`), встроенный `node:sqlite`
  (`DatabaseSync`, WAL), без ORM и нативных модулей.
- Express 5.3, Socket.IO 4.8, multer 2.5, bcryptjs 3.
- Голос: `livekit-server-sdk` (сервер), `livekit-client` (браузер, отдаётся с
  `/vendor`); LiveKit запускается отдельно.
- `@sapphi-red/web-noise-suppressor` — шумоподавление в звонках; опционально,
  сервер работает и без пакета.
- Фронтенд — один `public/index.html` (HTML+CSS+JS), без фреймворка, бандлера и
  сборки.

## Структура

```
index.js              весь сервер: Express-роуты, Socket.IO-события, LiveKit (~1800 строк)
db.js                 схема SQLite и миграции через addColumn()
public/index.html     весь веб-клиент (разметка, стили, скрипт)
public/voiceclarity/  DFN3 WASM-модель (~17 МБ, lazy; MIT/Apache)
scripts/setup.mjs     генерация .env и livekit.yaml
test/                 node:test: шумодав (all.js — входная точка)
docs/                 INSTALL.md, ADMIN.md
uploads/              файлы (UUID-имена) и uploads/avatars/ — в git не входят
mycord.db*            рабочая БД рядом с кодом — в git не входит
```

## Команды

```bash
npm ci
npm run setup         # .env и livekit.yaml со случайными ключами
npm start             # = node --env-file-if-exists=.env index.js, http://127.0.0.1:3000
npm test              # node --check + node test/all.js
livekit-server --dev  # локальный голос: ws://localhost:7880, devkey/secret
```

- Линтера и CI нет: перед изменениями — `npm test`, затем ручная проверка.
- `npm test` не спавнит процессы: все `*.test.js` импортируются в одном.
- Тест шумодава берёт ворклет прямо из `public/index.html` — ломать разметку
  `const MIC_WORKLET = ...` нельзя.

## Переменные окружения

`PORT` (3000), `HOST` (127.0.0.1), `NODE_ENV`, `ADMIN_NAME`, `INVITE_CODE`,
`LIVEKIT_URL`, `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`, `LIVEKIT_API_URL`.
Читаются из `.env` через `npm start`; переменная окружения имеет приоритет.
С `NODE_ENV=production` сервер завершается, если не заданы `LIVEKIT_*` и
`INVITE_CODE`.

## Стиль кода

- 2 пробела, точки с запятой, двойные кавычки; сервер — ESM.
- Идентификаторы и имена событий — английский; комментарии и тексты UI/ошибок —
  русский.
- Файлы монолитные: сервер в `index.js`, клиент в `index.html`; помощники
  сверху, использование ниже.
- Колбэк — всегда последний аргумент; ответ `{ ok: true }` или `{ error: "..." }`.
  Сокет-обработчики регистрируются через обёртку `on()`, которая ловит ошибки и
  не роняет процесс.
- SQL — только подготовленные выражения на месте, без ORM; новые колонки — через
  `addColumn()` в `db.js`.
- Клиент: `$ = (id) => document.getElementById(id)`, иконки в `ICON`, настройки в
  `localStorage`, запросы с `Authorization: Bearer <token>`.
- Новые зависимости — только при реальной необходимости.

## Важные решения

- Сервер слушает `127.0.0.1:3000` за обратным прокси; `trust proxy 1`, реальный
  IP из `X-Forwarded-For`.
- Аутентификация: токен-сессия на 30 дней в `sessions`; bcrypt cost 10; лимиты
  попыток входа и загрузок.
- Администратор — `ADMIN_NAME` или первый зарегистрированный пользователь; есть
  флаг `moderator`; действия пишутся в `audit` (последние 1000).
- Фичи (`FEATURES` в `index.js`, флаги `feat:<id>` в `settings`) по умолчанию
  выключены и переключаются админом на лету.
- Голос — комнаты LiveKit `voice-<channelId>`, токен на 6 часов; состояние в
  памяти `voiceMembers`.
- Шумодав клиентский (RNNoise WASM); флаг `ns_pro` включает HPF, гистерезис,
  de-click и ползунок силы (`mic.nsLevel`); в pro-режиме NS и AGC браузера
  выключаются, только когда включён наш шумодав; AEC оставлен.
- Флаг `ns_dfn` — DeepFilterNet3: модель self-hosted в `public/voiceclarity`,
  грузится только при включении; при ошибке/неподдержке — откат на RNNoise.
  Статистика underrun из ворклета → автоотключение; глубина меняется сообщением
  `set-attenuation` без пересоздания движка; `.wasm` отдаётся с недельным кэшем.
- Обратный прокси должен сжимать ответы (`encode zstd gzip` у Caddy): wasm
  ~17 МБ → ~10 МБ.
- Файлы: `/upload` до 25 МБ и 30 раз в час; аватар — только JPEG до 1 МБ;
  неиспользованные файлы чистятся каждые 6 часов.
- Перезапуск сервера из админки — намеренный `process.exit(1)`, чтобы
  systemd/Docker с `on-failure` подняли процесс.
- БД лежит рядом с кодом (`import.meta.dirname`), а не в CWD. Имя файла
  `mycord.db` историческое — не переименовывать без миграции, иначе на уже
  работающей установке появится пустая база.

## Нельзя

- Коммитить `mycord.db*`, `uploads/`, `.env`, `livekit.yaml` — там живые данные и
  секреты. Не добавлять их через `git add -f`.
- Менять имена socket-событий, поля payload и REST-роуты без синхронной правки
  `public/index.html`.
- Ломать контракт «колбэк последним аргументом» и формат `{ ok }` / `{ error }`.
- Добавлять бандлер/фреймворк во фронтенд: `public/index.html` отдаётся как есть.
- Хардкодить секреты и запускать прод без `LIVEKIT_*`/`INVITE_CODE`.
- Хранить пароли в открытом виде или обходить bcrypt/лимиты.
- Убирать мягкую деградацию шумоподавления: сервер обязан работать и без пакета.
- Считать, что есть линтер/CI: их нет; перед коммитом — `npm test` и ручная
  проверка.
