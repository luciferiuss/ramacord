# Ramacord

Чат с голосовыми каналами, который вы поднимаете на своём сервере. Один процесс
Node.js, встроенная SQLite, голос — через LiveKit. Без облаков, внешних баз и
телеметрии: все данные лежат рядом с кодом, на вашей машине.

> В этом репозитории только сервер и веб-клиент. Десктопной обёртки здесь нет —
> чат открывается в браузере.

## Возможности

- Текстовые каналы: ответы на сообщения, реакции, редактирование, закреплённые,
  поиск, упоминания `@ник`, непрочитанные, форматирование, предпросмотр ссылок.
- Личные сообщения, статусы («в сети», «отошёл», «не беспокоить», своя строка),
  профиль с «о себе» и датой регистрации.
- Голосовые каналы на LiveKit: вход/выход, список участников, заглушка и
  отключение участника администратором.
- Файлы до 25 МБ (не больше 30 в час), аватарки JPEG до 1 МБ. Неприкреплённые
  файлы автоматически удаляются.
- Шумоподавление в браузере: RNNoise из коробки, DeepFilterNet3 (PoC) —
  включается администратором.
- Роли администратора и модератора, баны, муты, журнал последних 1000 действий.
- Закрытая регистрация по коду приглашения, лимиты попыток входа и загрузок.
- Все необязательные функции выключены по умолчанию и включаются тумблерами в
  админ-панели на лету, без перезапуска.

## Требования

- Node.js 22.13 или новее (используется встроенный `node:sqlite`).
- [LiveKit](https://livekit.io) — только для голоса; без него чат работает.
- Обратный прокси с HTTPS (Caddy, Nginx) — для доступа не с localhost и для
  голоса: браузер пускает микрофон только на `https://` и `wss://`.

## Быстрый старт

```bash
git clone https://github.com/luciferiuss/ramacord.git
cd ramacord
npm ci
npm run setup        # создаст .env и livekit.yaml со случайными ключами
```

Дальше в двух терминалах:

```bash
livekit-server --config ./livekit.yaml   # голосовой сервер
npm start                                # чат: http://127.0.0.1:3000
```

`npm run setup` печатает код приглашения — он понадобится при регистрации.
Для быстрой пробы без настройки LiveKit можно запустить `livekit-server --dev`
и вернуть в `.env` пару `LIVEKIT_API_KEY=devkey`, `LIVEKIT_API_SECRET=secret`.

Откройте <http://127.0.0.1:3000>, зарегистрируйтесь — **первый аккаунт
становится администратором** (если `ADMIN_NAME` пуст). Затем в админ-панели:

- **Функции** — включить нужные возможности (по умолчанию выключены все);
- **Доступ** — сменить код приглашения, закрыть регистрацию;
- **Чаты** / **Голос** — каналы, пароли каналов, порядок;
- **Аккаунты** — модераторы, баны, сброс пароля.

## Настройки

Все настройки — переменные окружения. `npm start` читает их из `.env` в папке
проекта (файл в `.gitignore`). Полный список с комментариями — в
[`.env.example`](.env.example).

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `3000` | Порт HTTP-сервера |
| `HOST` | `127.0.0.1` | Адрес прослушивания. `0.0.0.0` — только если нет прокси с HTTPS |
| `NODE_ENV` | — | `production` включает проверки окружения при старте |
| `ADMIN_NAME` | первый аккаунт | Ник администратора (регистр не важен) |
| `INVITE_CODE` | пусто (регистрация открыта) | Код приглашения для регистрации |
| `LIVEKIT_URL` | `ws://localhost:7880` | Адрес LiveKit; в продакшене — `wss://` |
| `LIVEKIT_API_KEY` | `devkey` | Ключ LiveKit, тот же, что в конфиге сервера |
| `LIVEKIT_API_SECRET` | `secret` | Секрет LiveKit |
| `LIVEKIT_API_URL` | из `LIVEKIT_URL` | Адрес управления LiveKit (для заглушки) |
| `VOICE_TOKEN_TTL` | `10m` | Срок токена голоса; LiveKit продлевает его в активном звонке |
| `UPLOAD_PER_HOUR` | `30` | Файлов в час с одного аккаунта |
| `UPLOAD_USER_MB` | `250` | Мегабайт за сутки на аккаунт |
| `UPLOAD_TOTAL_MB` | `2048` | Мегабайт за сутки на весь сервер |
| `REG_LIMIT_IP` | `3` | Аккаунтов с одного IP за сутки |
| `REG_LIMIT_TOTAL` | `20` | Аккаунтов на сервер за сутки |

С `NODE_ENV=production` сервер не запустится, если не заданы `LIVEKIT_*` и
`INVITE_CODE` — это защита от случайного открытого сервера. Код приглашения —
от 12 символов, пароль канала — от 8.

## Установка на сервер

Пошаговая инструкция для Ubuntu/Debian: [docs/INSTALL.md](docs/INSTALL.md) —
Node.js, LiveKit, systemd, Caddy с HTTPS, файрвол, первый вход, обновление и
резервные копии. Возможности админ-панели: [docs/ADMIN.md](docs/ADMIN.md).
Полное руководство по всем функциям, шумодаву и настройкам —
[ИНСТРУКЦИЯ.md](ИНСТРУКЦИЯ.md).

Коротко: сервер слушает `127.0.0.1:3000`, перед ним Caddy терминирует HTTPS,
LiveKit доступен по `wss://` через свой поддомен, UDP-порты LiveKit открыты
напрямую.

## Структура проекта

```
index.js              сервер: REST, Socket.IO, LiveKit, загрузки, админ-логика
db.js                 схема SQLite и миграции
public/index.html     весь веб-клиент (HTML + CSS + JS, без сборки)
public/voiceclarity/  WASM-модель DeepFilterNet3 (~17 МБ, MIT/Apache)
test/                 node:test: шумодав, DSP-гейт
scripts/setup.mjs     генерация .env и livekit.yaml
docs/                 установка и администрирование
```

Файл базы называется `mycord.db` (историческое имя) и создаётся рядом с кодом
при первом запуске. Папка `uploads/` тоже появляется сама.

## Тесты

```bash
npm test
```

Проверяет синтаксис сервера и гоняет `node:test` для шумоподавления: тест берёт
ворклет прямо из `public/index.html`, поэтому проверяется именно тот код,
который уезжает в браузер.

## Безопасность

- `.env`, `livekit.yaml`, `mycord.db` и `uploads/` не попадают в git — не
  добавляйте их принудительно: в базе хеши паролей и действующие токены входа.
- Резервная копия базы (админ-панель → «Сервер» → «Резервная копия базы»)
  содержит те же секреты — храните её так же, как пароли.
- Пароли хранятся только в виде bcrypt-хешей, вход ограничен по IP и нику.
- Уязвимости: см. [SECURITY.md](SECURITY.md).
