# Ramacord

Чат с голосовыми каналами, который вы поднимаете на своём сервере: текстовые
каналы, личные сообщения, файлы, голос, демонстрация экрана и камера. Один
процесс Node.js, база SQLite рядом с кодом, голос через LiveKit. Без облаков,
подписок и телеметрии - все данные лежат на вашей машине.

В этом репозитории только сервер и веб-клиент. Десктопной - ПК(создается через Electron) и Android(через Android Studio SDK) версий нет:
чат открывается в браузере.

> **Ниже - полная инструкция с нуля**: покупка сервера, домен, подключение по
> SSH, установка, HTTPS, первый вход. Если вы никогда не работали с серверами -
> просто идите по шагам и копируйте команды. Всё, что нужно, есть в этом файле.

## 1. Что это такое

```
браузер ──HTTPS──► Caddy ──► Node.js (index.js) ──► mycord.db (SQLite)
   │                              │
   └──────── wss:// ─────────► LiveKit (голос, экран, камера)
```

- **Ramacord** (Node.js) - отдаёт сайт, API, сообщения в реальном времени,
  загрузки и админку.
- **SQLite** - файл `mycord.db` рядом с кодом: аккаунты, сообщения, каналы,
  настройки, журнал.
- **LiveKit** - отдельный сервер голоса и видео. Без него работает чат, но не
  работает голос.
- **Caddy** - HTTPS и проксирование. Нужен, чтобы браузер разрешил микрофон:
  он работает только на `https://`.

Всё состояние - база и папка `uploads/`. Больше ничего хранить не нужно.

## 2. Что понадобится

| Что | Зачем | Сколько стоит |
|---|---|---|
| VPS с Ubuntu 24.04, 2 ГБ RAM, 20 ГБ диска | там будет работать чат | ~5-10 $ в месяц |
| Домен (например `example.com`) | адрес вида `chat.example.com` и HTTPS | ~300-1500 ₽ в год |
| 30-60 минут | установка | - |
| Браузер | проверить голос | - |

Никаких навыков программирования не нужно: все команды ниже можно копировать
целиком. Единственное, что придётся делать руками - вписывать свой домен и
пароли.

**Что означают слова, которые встретятся дальше:**

- **VPS / сервер** - удалённый компьютер, который работает круглосуточно. Вы
  управляете им командами.
- **root** - главный администратор сервера. Пароль от него пришлёт провайдер.
- **SSH** - способ подключиться к серверу из своего компьютера.
- **Терминал** - окно, куда вводят команды. На Windows это PowerShell.
- **Домен** - имя сайта. `chat.example.com` - поддомен, буквально «чат на
  домене example.com».
- **DNS** - настройка, которая говорит интернету, по какому адресу искать ваш
  домен.

## 3. Покупаем сервер

1. Зарегистрируйтесь у любого хостинга. Примеры: Timeweb Cloud, Aeza, Hetzner,
   DigitalOcean, Vultr (это не реклама - подойдёт любой).
2. Создайте сервер со следующими параметрами:
   - **ОС**: Ubuntu 24.04 LTS (или 22.04);
   - **CPU**: 2 ядра;
   - **RAM**: 2 ГБ (минимум 1 ГБ);
   - **Диск**: 20 ГБ SSD;
   - **Публичный IPv4**: обязательно;
   - **Доступ**: по паролю root (если хостинг просит SSH-ключ - см. примечание
     ниже).
3. Запишите в блокнот:
   - **IP-адрес** сервера, например `203.0.113.45`;
   - **пароль root** (придёт на почту или покажется один раз).

> **Если хостинг требует SSH-ключ.** Выберите вариант «пароль» при создании.
> Если нельзя - на своём компьютере выполните `ssh-keygen -t ed25519`, затем
> скопируйте содержимое файла `~/.ssh/id_ed25519.pub` в поле «SSH key» у
> хостинга. Вход по паролю тогда не понадобится.

> **Если сервер за NAT** (некоторые дешёвые тарифы): нужен именно публичный
> IPv4, иначе снаружи не подключиться.

## 4. Покупаем домен и настраиваем DNS

1. Купите домен у регистратора (reg.ru, Namecheap, Cloudflare и т. п.).
2. Зайдите в панель управления DNS вашего домена.
3. Добавьте **две записи** типа `A`:

   | Имя (Host) | Тип | Значение |
   |---|---|---|
   | `chat` | A | IP вашего сервера |
   | `livekit` | A | IP вашего сервера |

   В некоторых панелях поле «Имя» заполняют полным адресом:
   `chat.example.com`. Ориентируйтесь на подсказку панели.

4. Если домен обслуживает **Cloudflare** - обязательно выключите оранжевое
   облако (прокси) у обеих записей, оставьте «DNS only» (серое облако).
   Иначе LiveKit и WebSocket могут не работать.

5. Подождите 5-30 минут и проверьте на сервере (после подключения по SSH):

   ```bash
   getent hosts chat.example.com
   getent hosts livekit.example.com
   ```

   Обе команды должны показать IP вашего сервера.

> Дальше в командах встречается `example.com`. **Везде замените его на свой
> домен.** Удобно сначала скопировать инструкцию в блокнот и заменить.

## 5. Подключаемся к серверу по SSH

### Windows 10/11

1. Нажмите `Win`, напишите `PowerShell`, откройте.
2. Введите (вместо `IP` - ваш IP-адрес):

   ```powershell
   ssh root@IP
   ```

3. Первый раз появится вопрос про отпечаток ключа - напишите `yes` и нажмите
   Enter.
4. Введите пароль root. **Пароль не отображается** - это нормально, просто
   вставьте его и нажмите Enter.

Если пишет `ssh не является внутренней или внешней командой` - включите
компонент: «Параметры» → «Приложения» → «Дополнительные компоненты» → «Клиент
OpenSSH» → «Установить». Либо поставьте программу Termius (бесплатная, есть
подсказки).

### macOS / Linux

Откройте «Терминал» и выполните `ssh root@IP`.

### Телефон

Приложение Termius: новое подключение → хост = IP, пользователь = `root`,
пароль.

### Как понять, что получилось

Строка приглашения изменится на что-то вроде:

```
root@server:~#
```

Проверьте:

```bash
whoami
```

Должно вывести `root`. Всё остальное дальше выполняется **на сервере**, а не на
вашем компьютере.

> **Копирование в терминал.** В Windows PowerShell вставка - правой кнопкой
> мыши или `Ctrl+V`. В Linux/macOS - `Ctrl+Shift+V` или правая кнопка.

## 6. Готовим сервер

Скопируйте блок целиком и нажмите Enter. Он обновит систему и поставит нужные
программы.

```bash
apt update && apt upgrade -y
apt install -y curl git nano ufw ca-certificates sqlite3 gnupg
timedatectl set-timezone Europe/Moscow
```

- `apt update/upgrade` - обновление системы;
- `git` - скачать проект;
- `nano` - простой редактор файлов;
- `ufw` - файрвол;
- `sqlite3` - резервные копии базы.

> Если при обновлении появится фиолетовый экран с вопросом - нажмите Enter
> (согласиться с предложенным вариантом).

Проверьте, что сервер видит интернет:

```bash
curl -I https://github.com
```

Должна быть строка `HTTP/2 200`.

## 7. Ставим Node.js

Ramacord требует Node.js 22.13 или новее.

```bash
curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
apt install -y nodejs
node -v
```

Последняя команда должна показать `v22.x.x` (или новее, например `v24.x`).

Если показывает старую версию (`v18`, `v20`) - значит, Node уже был установлен
из репозитория Ubuntu. Удалите и повторите:

```bash
apt remove -y nodejs
curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
apt install -y nodejs
node -v
```

## 8. Ставим LiveKit

LiveKit - отдельная программа для голоса.

```bash
curl -sSL https://get.livekit.io | bash
livekit-server --version
```

Должна показаться версия, например `livekit-server version 1.13.11`.

Если команда не найдена - проверьте путь:

```bash
ls -la /usr/local/bin/livekit-server
```

Скрипт установки кладёт бинарник туда. Если он оказался в другом месте, дальше
в службе LiveKit укажите правильный путь в `ExecStart`.

## 9. Скачиваем Ramacord и ставим зависимости

```bash
git clone https://github.com/luciferiuss/ramacord.git /opt/ramacord
cd /opt/ramacord
npm ci
npm run setup
```

Что произойдёт:

- `git clone` - скачает код в `/opt/ramacord`;
- `npm ci` - поставит зависимости (может занять минуту);
- `npm run setup` - создаст два файла: `.env` (настройки) и `livekit.yaml`
  (конфиг голоса) со случайными ключами.

**Скопируйте из вывода `npm run setup` код приглашения** - он понадобится при
регистрации. Если забудете, его можно посмотреть позже:

```bash
grep INVITE_CODE /opt/ramacord/.env
```

## 10. Настраиваем .env

Откройте файл в редакторе:

```bash
nano /opt/ramacord/.env
```

Управление в nano: стрелки - перемещение, `Ctrl+O` → Enter - сохранить,
`Ctrl+X` - выйти.

Найдите и измените строки (остальные не трогайте):

```ini
NODE_ENV=production
HOST=127.0.0.1
ADMIN_NAME=
INVITE_CODE=ваш_код_из_setup
LIVEKIT_URL=wss://livekit.example.com
LIVEKIT_API_KEY=...
LIVEKIT_API_SECRET=...
```

- `NODE_ENV=production` - включает проверки для боевого сервера;
- `HOST=127.0.0.1` - сервер доступен только через Caddy (так безопаснее);
- `ADMIN_NAME` - пока оставьте пустым, впишете ник после регистрации;
- `INVITE_CODE` - код приглашения (от 12 символов). Оставьте сгенерированный
  или впишите свой;
- `LIVEKIT_URL` - `wss://livekit.` + ваш домен;
- ключи `LIVEKIT_API_KEY`/`LIVEKIT_API_SECRET` уже сгенерированы - оставьте.

Сохраните (`Ctrl+O`, Enter) и выйдите (`Ctrl+X`).

Проверьте, что ключи в `.env` и `livekit.yaml` совпадают (это делает `setup`,
но на всякий случай):

```bash
grep LIVEKIT_API_KEY /opt/ramacord/.env
grep -A1 '^keys:' /opt/ramacord/livekit.yaml
```

И закройте файлы с секретами от посторонних:

```bash
chmod 600 /opt/ramacord/.env /opt/ramacord/livekit.yaml
```

## 11. Запускаем LiveKit как службу

Создайте файл службы (скопируйте блок целиком):

```bash
cat > /etc/systemd/system/livekit.service <<'EOF'
[Unit]
Description=LiveKit Server
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=/opt/ramacord
ExecStart=/usr/local/bin/livekit-server --config /opt/ramacord/livekit.yaml
Restart=on-failure
RestartSec=3
LimitNOFILE=65536

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable --now livekit
systemctl status livekit --no-pager
```

В статусе должно быть `active (running)`. Если нет - смотрите ошибки:

```bash
journalctl -u livekit -n 50 --no-pager
```

> Если в `livekit.yaml` стоит `use_external_ip: false`, а голос не
> подключается - замените на `true` (`nano /opt/ramacord/livekit.yaml`) и
> перезапустите: `systemctl restart livekit`. `true` нужен, если сервер за NAT
> или в облаке без публичного IP на сетевом интерфейсе.

## 12. Запускаем Ramacord как службу

```bash
cat > /etc/systemd/system/ramacord.service <<'EOF'
[Unit]
Description=Ramacord
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=/opt/ramacord
ExecStart=/usr/bin/node --env-file-if-exists=.env index.js
Restart=on-failure
RestartSec=3

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable --now ramacord
systemctl status ramacord --no-pager
```

Проверьте, что сайт отвечает локально:

```bash
curl -I http://127.0.0.1:3000
```

Должно быть `HTTP/1.1 200 OK`. Если нет:

```bash
journalctl -u ramacord -n 50 --no-pager
```

Самая частая причина - ошибка в `.env` (сервер пишет, каких переменных не
хватает).

> Служба запускается от `root`, потому что так проще. Если хотите отдельного
> пользователя - создайте его, сделайте `chown -R имя:имя /opt/ramacord` и
> добавьте `User=имя` в блок `[Service]`.

> Кнопка «Перезапустить сервер» в админке работает благодаря
> `Restart=on-failure`: процесс завершается с кодом 1, systemd поднимает его.

## 13. Caddy и HTTPS

Caddy сам получит бесплатный сертификат Let's Encrypt - для этого DNS уже
должен указывать на сервер, а порты 80/443 быть открыты.

Установка:

```bash
apt install -y debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' \
  | gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' \
  | tee /etc/apt/sources.list.d/caddy-stable.list
apt update && apt install -y caddy
```

Файл настроек:

```bash
nano /etc/caddy/Caddyfile
```

Приведите его к такому виду (замените `example.com` на свой домен):

```
chat.example.com {
	encode zstd gzip
	reverse_proxy 127.0.0.1:3000
}

livekit.example.com {
	reverse_proxy 127.0.0.1:7880
}
```

- `encode zstd gzip` - сжатие: модель шумодава ~17 МБ по сети едет примерно
  как 10 МБ;
- первый блок - сайт, второй - голос.

Сохраните и проверьте:

```bash
caddy validate --config /etc/caddy/Caddyfile
systemctl reload caddy
systemctl status caddy --no-pager
```

Откройте в браузере `https://chat.example.com`. Должна открыться страница
входа Ramacord с зелёным замком.

> Если домен ещё не «созрел», Caddy не получит сертификат. Подождите и
> выполните `systemctl reload caddy` ещё раз. Логи: `journalctl -u caddy -n 50
> --no-pager`.

> Если на сервере уже стоял nginx/apache и занял порты 80/443 - остановите его
> (`systemctl disable --now nginx`) или настройте проксирование в нём.

## 14. Файрвол

```bash
ufw allow 22/tcp
ufw allow 80,443/tcp
ufw allow 7881/tcp
ufw allow 50000:60000/udp
ufw enable
```

На вопрос про разрыв SSH-соединения ответьте `y`.

Что открыто и зачем:

| Порт | Зачем |
|---|---|
| 22/tcp | SSH, чтобы вы могли подключаться |
| 80, 443/tcp | сайт и HTTPS |
| 7881/tcp | LiveKit, резервный канал |
| 50000-60000/udp | медиа голоса и видео |

Порты `3000` и `7880` наружу **не открывайте**: к ним ходит только Caddy.

> Если у хостинга есть свой файрвол в панели - откройте те же порты и там.

## 15. Первый вход и настройка

1. Откройте `https://chat.example.com`.
2. Нажмите «Создать аккаунт»: ник, пароль (от 6 символов), код приглашения.
3. **Первый зарегистрированный аккаунт становится администратором** (если
   `ADMIN_NAME` пуст).
4. Впишите свой ник в `.env`, чтобы роль не зависела от порядка регистрации:

   ```bash
   nano /opt/ramacord/.env     # ADMIN_NAME=ваш_ник
   systemctl restart ramacord
   ```

5. Зайдите в «Админ-панель»:
   - **Функции** - включите нужные (по умолчанию выключено всё необязательное);
   - **Доступ** - смените код приглашения на свой (от 12 символов), при желании
     включите «Регистрация закрыта»;
   - **Чаты** / **Голос** - создайте каналы, поставьте пароли, настройте порядок;
   - **Аккаунты** - назначьте модераторов.
6. Проверьте голос (следующий раздел).
7. Настройте резервные копии (раздел 18).

> Код приглашения можно посмотреть так:
> `grep INVITE_CODE /opt/ramacord/.env`. Если вы сменили его в админке, он
> хранится в базе, и `.env` больше не актуален.

---

## 16. Проверяем голос

1. Зайдите с компьютера в `https://chat.example.com`, откройте голосовой канал.
2. Браузер спросит доступ к микрофону - разрешите.
3. Подключите второй аккаунт (телефон или другое окно) в тот же канал.
4. Проверьте: слышно обоих, кнопки «Микрофон» и «Звук» работают, имя
   подсвечивается при разговоре.

Если не работает:

- страница открыта по `http://` - микрофон не дадут, нужен `https://`;
- в логах LiveKit ошибки:
  `journalctl -u livekit -n 50 --no-pager`;
- закрыты порты `7881/tcp` и `50000-60000/udp`;
- `LIVEKIT_URL` не `wss://`;
- `livekit.example.com` не открывается по HTTPS.

## 17. Обновление

```bash
cd /opt/ramacord
git pull
npm ci
systemctl restart ramacord
```

База и `uploads/` не затрагиваются. Если менялся клиент
(`public/index.html`) - перезапуск не обязателен, но пользователям нужно
обновить страницу (`Ctrl+F5`).

## 18. Резервные копии

Самый простой способ - админ-панель → **Сервер** → «Резервная копия базы».
Скачается файл `mycord-ГГГГ-ММ-ДД.db`. **Внутри хеши паролей и токены входа** -
храните его как пароль и не выкладывайте.

Копия на сервере без остановки:

```bash
sqlite3 /opt/ramacord/mycord.db ".backup '/var/backups/ramacord-$(date +%F).db'"
tar czf /var/backups/uploads-$(date +%F).tar.gz -C /opt/ramacord uploads
```

Файлы (`uploads/`) копируются отдельно. Храните бэкапы не на том же диске:
скачайте к себе или отправьте в облако.

Восстановление: остановить службу, положить файл базы на место
`/opt/ramacord/mycord.db` (и удалить `mycord.db-wal`/`mycord.db-shm`),
запустить службу.

## 19. Все функции

Необязательные функции включаются администратором на вкладке «Функции» и
действуют сразу у всех, без перезапуска. По умолчанию выключено всё, кроме
базового чата и входа.

### Каналы

- **Текстовые** - история сообщений, файлы, поиск, закреплённые.
- **Голосовые** - комнаты LiveKit; переписки там нет.
- **Личные сообщения** - отдельный раздел, только для двоих; администратор
  чужие ЛС не читает.

Создание, переименование, порядок и пароль - у администратора. Пароль канала -
**от 8 символов**, хранится в виде хеша. Смена пароля сбрасывает доступ у всех.
Каналы `general`, `random`, `голосовой` создаются при первом запуске; удалить
последний текстовый канал нельзя.

### Сообщения

| Функция | Что делает | Ограничения |
|---|---|---|
| Отправка | Enter или кнопка | до 2000 символов |
| Ответ | цитата над сообщением, переход к оригиналу | - |
| Редактирование | правка своих, пометка «(изменено)» | только свои и 24 часа |
| Удаление | у автора остаётся «Сообщение удалено» | свои 24 часа; админ - любое |
| Реакции | 8 эмодзи со счётчиками | повтор снимает реакцию |
| Медиа | плееры видео/аудио, просмотр картинок | - |
| Вставка файлов | Ctrl+V и перетаскивание | те же лимиты, что у загрузки |
| Ссылки | `https?://` становятся кликабельными | только http/https |
| Предпросмотр ссылок | карточка «сайт / заголовок / описание» | сервер сам открывает страницу: только публичные адреса, не чаще 10 раз в минуту, до 300 КБ |
| Форматирование | `код`, **жирный**, *курсив*, ~~зачёркнутый~~, ```блок кода``` | - |
| «Печатает…» | индикатор набора | не чаще раза в 2 секунды |
| Поиск | по текущему каналу | от 2 символов |
| Закреплённые | список закреплённого | закрепляет админ/модератор; в ЛС нельзя |
| Непрочитанные | бейджи «N»/«@M», счётчик в заголовке | сбрасывается при открытии |
| Упоминания | подсветка `@ник` | - |
| Уведомления | системные окна и звук | настраиваются; «не беспокоить» подавляет |

### Личное общение

- **Личные сообщения** - переписка двух человек.
- **Статусы** - «В сети», «Отошёл», «Не беспокоить», своя строка (до 60
  символов).
- **Профиль** - «о себе» (до 200 символов), дата регистрации, где человек в
  голосе.
- **Очистка и удаление ЛС** - необратимо и сразу у обоих.

### Файлы

- До **25 МБ** за файл, не больше **30 файлов в час** с аккаунта.
- Дневные квоты: **250 МБ** на аккаунт и **2 ГБ** на сервер (меняются в `.env`).
- Имена на диске - UUID; всё, кроме картинок, отдаётся как скачивание.
- Неприкреплённые файлы удаляются автоматически (раз в 6 часов, старше суток).
- Аватар - только JPEG до 1 МБ, клиент сжимает до 256×256.

### Голос

- Вход кликом по каналу; микрофон включается сам, при отказе вы слушатель.
- Кнопки: «Микрофон», «Звук», «Выйти из голоса», «Показать экран», камера.
- Правый клик по участнику: личная громкость и заглушка.
- Модератор: «Заглушить для всех», «Выкинуть из голоса». Админ ещё
  «Перенести в канал» (перенос даёт доступ к закрытому каналу).
- «Заглушить всех» - все, кроме администратора, включая заходящих позже.
- Кик - не бан: человек может вернуться. Бан - в «Аккаунтах», вход пропадает.
- **Токен голоса живёт 10 минут** (`VOICE_TOKEN_TTL`). LiveKit сам продлевает
  его, пока вы в комнате, поэтому звонки не рвутся. Короткий срок нужен, чтобы
  выгнанный не мог вернуться со сохранённым токеном.

### Экран и камера

- Разрешение: 720p, 1080p (по умолчанию), 1440p, до 4K; частота: 15, 30 (по
  умолчанию), 60. Битрейт подбирается сам (1080p - 3-9 Мбит/с).
- В браузере источник выбирается системным окном; в десктопном приложении -
  своим списком и звуком компьютера.
- Камера: 720p, 30 кадров/с, ~1,5 Мбит/с; фронтальная зеркалится.

### Клавиши

- «Говорить по клавише (рация)» и «Вкл/выкл микрофон» назначаются в настройках.
- В браузере работают, пока вкладка активна; в десктопном приложении - поверх
  других программ.

## 20. Шумоподавление и микрофон

Настройки открываются шестерёнкой в панели голоса, пока вы в канале. Они
хранятся в браузере у каждого свои.

1. **«Шумоподавление»** - базовый RNNoise (WASM), по умолчанию выключен. При
   включении в звонок идёт очищенный звук. Если сервер не отдал модуль - кнопка
   покажет ошибку и вернётся назад, чат при этом работает.
2. **«Усиленное (DeepFilterNet3)»** - нейросетевой шумодав. Виден, только если
   администратор включил функцию `ns_dfn`. Загружает модель ~17 МБ (первый раз
   долго), включает базовый шумодав, при нехватке мощности сам выключается с
   сообщением, при ошибке откатывается на RNNoise.
3. **«Сила шумоподавления»** (0-100 %, по умолчанию 50 %) - насколько сильно
   давить шум; в DeepFilterNet3 меняется на лету.
4. **«Громкость микрофона»** (0-200 %, по умолчанию 100 %) - усиление.
5. **«Чувствительность»** (0-100, по умолчанию 0 = выключено) - порог гейта:
   тише порога звук не проходит. 100 - нужно говорить громко.
6. **Улучшенный режим (`ns_pro`)** - обрезка низов ~90 Гц, гистерезис, плавные
   атака/спад, удержание, подавление щелчков. В нём чувствительность при первом
   включении ставится на 20 %.

Что важно знать:

- Эхоподавление браузера включено всегда; шумоподавление и автоусиление
  браузера выключаются, только когда включён улучшенный режим и наш шумодав
  (чтобы не было двойной обработки). Применяется при входе в канал.
- Выбора микрофона/динамика в интерфейсе нет - используется устройство по
  умолчанию из системы.
- **Можно** включать и выключать шумодав в любой момент, крутить силу и
  чувствительность.
- **Не стоит** включать DeepFilterNet3 на слабом ноутбуке или телефоне - будет
  задержка и автоотключение; начните с RNNoise.
- **Не стоит** ставить силу 100 % и громкость 200 % одновременно - получите
  артефакты и «металлический» голос.
- Не влезайте в `const MIC_WORKLET` в `public/index.html`: на нём держится тест
  `npm test` и весь DSP-гейт.

## 21. Админ-панель

Кнопка «Админ-панель» (у модератора - «Модерация»).

### Аккаунты (доступна модератору)

- Поиск по нику; состояние: в сети / не в сети / в голосе / заглушён /
  заблокирован.
- **Заблокировать** - сразу выкидывает из чата и голоса, вход запрещён.
- Меню «⋯»: «Заглушить для всех», «Выкинуть из голоса», «Перенести в канал»,
  «Сделать модератором», «Сбросить пароль», «Удалить аккаунт».
- «Сбросить пароль» показывает временный пароль **один раз** и рвёт все сессии.
- «Удалить аккаунт» **необратимо**: сообщения остаются, личные переписки
  удаляются, ник можно занять заново.

### Голос

- «Заглушить всех» / «Снять заглушку со всех» - на всех, кроме администратора,
  включая тех, кто зайдёт позже.

### Чаты

- «Удалить все чаты» - стирает сообщения и файлы во всех каналах, каналы
  остаются. **Необратимо.**
- «Очистить один канал» - то же для выбранного. **Необратимо.**
- «Автоочистка» - одноразовое удаление через 7 дней; до срока можно отменить.

### Доступ

- «Код приглашения» - «Сменить», **от 12 до 64 символов**; старый код перестаёт
  работать для новых.
- «Регистрация закрыта» - новые аккаунты нельзя создать даже с кодом.
- «Режим обслуживания» - все, кроме администратора, отключаются и не могут
  войти.

### Сервер

- Статистика: онлайн, в голосе, аккаунтов, сообщений, размер базы и файлов,
  время работы, PID, версия Node.
- Предупреждение, если файлы на диске новее запущенного процесса - значит,
  обновили, а службу не перезапустили. Клиенту (`public/index.html`) перезапуск
  не нужен, достаточно обновить страницу.
- «Резервная копия базы» - скачивает `mycord.db` (внутри хеши и токены).
- «Неиспользуемые файлы» - удаляет загрузки, не прикреплённые к сообщениям;
  файлы моложе 15 минут не трогает.
- «Объявление для всех» - окно у всех, кто онлайн (до 1000 символов).
- «Перезапустить сервер» - процесс завершается, systemd поднимает его снова.
  Без менеджера процессов сервер останется лежать.

### Журнал

Последние 200 действий (в базе хранится 1000): кто, что, когда. Только чтение.

### Функции

Все необязательные возможности с тумблерами по группам «Чат», «Личное общение»,
«Голос». Включение действует сразу всем и пишется в журнал.

## 22. Настройки сервера

`npm start` читает `.env` из папки проекта; переменная окружения имеет приоритет
над файлом. После правки - `systemctl restart ramacord`.

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `PORT` | `3000` | порт HTTP |
| `HOST` | `127.0.0.1` | адрес прослушивания; снаружи - Caddy |
| `NODE_ENV` | - | `production` включает проверки при старте |
| `ADMIN_NAME` | первый аккаунт | ник администратора |
| `INVITE_CODE` | пусто | код приглашения (12+ символов) |
| `LIVEKIT_URL` | `ws://localhost:7880` | адрес LiveKit, в проде `wss://` |
| `LIVEKIT_API_KEY` | `devkey` | ключ LiveKit |
| `LIVEKIT_API_SECRET` | `secret` | секрет LiveKit |
| `LIVEKIT_API_URL` | из `LIVEKIT_URL` | адрес управления LiveKit |
| `VOICE_TOKEN_TTL` | `10m` | срок токена голоса |
| `UPLOAD_PER_HOUR` | `30` | файлов в час с аккаунта |
| `UPLOAD_USER_MB` | `250` | мегабайт за сутки на аккаунт |
| `UPLOAD_TOTAL_MB` | `2048` | мегабайт за сутки на сервер |
| `REG_LIMIT_IP` | `3` | аккаунтов с одного IP за сутки |
| `REG_LIMIT_TOTAL` | `20` | аккаунтов на сервер за сутки |

С `NODE_ENV=production` сервер не стартует без `LIVEKIT_*` и `INVITE_CODE` - это
защита от случайно открытого сервера.

## 24. Что можно и нельзя трогать

### Можно

| Что | Как |
|---|---|
| Функции | админка → «Функции» |
| Каналы, порядок, пароли | интерфейс администратора |
| Регистрация, код, обслуживание | «Доступ» |
| Аккаунты: бан, мут, модератор, сброс пароля | «Аккаунты» |
| Очистка чатов | «Чаты» (осторожно, необратимо) |
| Объявление, бэкап, перезапуск | «Сервер» |
| Настройки микрофона | у каждого свои, в панели голоса |
| Лимиты и адреса | `.env` + перезапуск |

### Нельзя

| Что | Почему |
|---|---|
| Удалять или пересоздавать `mycord.db`, `-wal`, `-shm` | это живые данные |
| Удалять `uploads/` | файлы и аватарки пользователей |
| Коммитить `.env`, `livekit.yaml`, `mycord.db`, `uploads/` | секреты и личные данные |
| Запускать прод с `devkey`/`secret` или без `INVITE_CODE` | голос и регистрация открыты всем |
| Ставить `HOST=0.0.0.0` без прокси с HTTPS | сервер открыт напрямую, микрофон не работает |
| Менять имена socket-событий, поля payload, REST-роуты | без правки клиента всё развалится |
| Убирать bcrypt, лимиты входа и загрузок | ослабление безопасности |
| Править `const MIC_WORKLET` и разметку теста | сломает `npm test` и DSP-гейт |
| Править `db.js` без миграции через `addColumn` | потеряете данные на живой базе |

## 25. Безопасность

Уже сделано в коде:

- пароли - только bcrypt, сравнение без утечки по времени;
- сессии - случайные токены на 30 дней, отзываются при выходе, бане, смене
  пароля;
- регистрация по коду от 12 символов с лимитами;
- загрузки с UUID-именами, лимитами и `nosniff`;
- каналы с паролем: bcrypt, лимит попыток;
- предпросмотр ссылок не ходит в localhost, приватные сети и метаданные облака,
  проверяет адрес в момент соединения;
- каждое админ-действие проверяется и пишется в журнал;
- голосовой токен 10 минут, после кика/бана старый умирает максимум за 10
  минут;
- секретов в коде нет - всё в `.env`.

Что сделать вам:

1. Не открывайте наружу порты `3000` и `7880`.
2. Держите `HOST=127.0.0.1` и HTTPS через Caddy.
3. Смените код приглашения и не публикуйте его.
4. Когда все свои зарегистрировались - включите «Регистрация закрыта».
5. Не используйте `devkey`/`secret` на боевом сервере.
6. Делайте бэкапы и храните их как пароли: внутри токены входа.
7. Регулярно обновляйтесь (`git pull && npm ci && systemctl restart ramacord`).

Сообщить об уязвимости: откройте приватный отчёт в GitHub (вкладка
**Security** → **Report a vulnerability**) или напишите автору
[@luciferiuss](https://github.com/luciferiuss).

## 26. Частые проблемы

| Симптом | Причина и решение |
|---|---|
| `ssh` не распознан | включите «Клиент OpenSSH» в Windows или поставьте Termius |
| `Permission denied` при SSH | неверный пароль/логин; проверьте, что хостинг не требует ключ |
| Домен не открывается | DNS ещё не обновился (до 30 минут) или запись не `A` на IP |
| Caddy не получает сертификат | порты 80/443 закрыты, DNS неверный или домен проксируется Cloudflare |
| `502 Bad Gateway` | служба Ramacord не запущена: `systemctl status ramacord` |
| «Не заданы переменные окружения» | `.env` не найден/неполный; проверьте `NODE_ENV`, `LIVEKIT_*`, `INVITE_CODE` |
| Голос не подключается | `LIVEKIT_URL` без `wss://`, закрыты 7881/tcp и UDP, `livekit.` домен не проксируется |
| Микрофон не спрашивается | страница по `http://` - нужен HTTPS |
| «Нет доступа к микрофону» | браузер запретил; вы в канале как слушатель |
| Долго включается DeepFilterNet3 | ~17 МБ WASM; проверьте `encode zstd gzip` в Caddy |
| Шумодав сам выключился | не хватает CPU: выключите DeepFilterNet3, оставьте RNNoise |
| «С этого адреса уже создано слишком много аккаунтов» | лимит регистраций; подождите сутки или поднимите `REG_LIMIT_IP` |
| «Дневной лимит загрузок» | квота; подождите или поднимите `UPLOAD_USER_MB`/`UPLOAD_TOTAL_MB` |
| «Пароль канала: от 8 символов» | новый минимум пароля канала |
| «Код приглашения: от 12 до 64 символов» | новый минимум кода |
| Кнопка «Перезапустить сервер» не поднимает сервер | нет systemd/PM2; проверьте `systemctl status ramacord` |
| После обновления старый интерфейс | `Ctrl+F5`: браузер закэшировал страницу |
| Забыл код приглашения | `grep INVITE_CODE /opt/ramacord/.env`; если меняли в админке - смотрите в «Доступ» |
| Забыл пароль администратора | временный пароль выдаёт другой админ; если админ один - смотрите список аккаунтов: `sqlite3 /opt/ramacord/mycord.db "select id,name from users order by id;"` |
| Кончилось место | почистите `uploads/` и старые бэкапы: `du -sh /opt/ramacord/*` |

Полезные команды:

```bash
systemctl status ramacord --no-pager     # работает ли чат
systemctl status livekit --no-pager      # работает ли голос
journalctl -u ramacord -n 50 --no-pager  # логи чата
journalctl -u livekit -n 50 --no-pager   # логи голоса
systemctl restart ramacord               # перезапуск чата
systemctl restart livekit                # перезапуск голоса
curl -I http://127.0.0.1:3000            # отвечает ли чат локально
```
