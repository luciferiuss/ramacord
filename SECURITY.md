# Безопасность

## Как сообщить об уязвимости

Не открывайте публичный issue с деталями эксплуатации. Используйте приватный
отчёт через GitHub: вкладка **Security** → **Report a vulnerability**
(Security Advisories). Если такой возможности нет — напишите автору
[@luciferiuss](https://github.com/luciferiuss) и укажите версию, шаги
воспроизведения и возможные последствия.

Мы постараемся ответить в течение недели и согласовать срок раскрытия.

## Поддерживаемые версии

Исправления выходят для последней версии из ветки `main`. Перед отчётом
проверьте, что проблема воспроизводится на свежем `git pull`.

## Что считается уязвимостью

- Обход аутентификации, захват чужого аккаунта, эскалация до администратора.
- Чтение чужих личных сообщений или файлов.
- SQL-инъекции, XSS, подделка запросов от имени другого пользователя.
- Обход лимитов входа, загрузок или кода приглашения.
- Утечка `.env`, `livekit.yaml`, `mycord.db` или токенов сессий.

## Базовая защита при развёртывании

- HTTPS обязателен: сервер слушает `127.0.0.1`, снаружи — только обратный
  прокси (Caddy/Nginx). Не ставьте `HOST=0.0.0.0`, если нет другой защиты.
- `NODE_ENV=production` — сервер не стартует с тестовыми ключами LiveKit и без
  кода приглашения.
- Свои ключи LiveKit вместо `devkey`/`secret`; `livekit.yaml` — только на
  сервере, права `600`.
- Код приглашения — случайный, не короче 8 символов; после регистрации своих
  включите «Регистрация закрыта».
- `.env`, `mycord.db`, `uploads/` и резервные копии не публикуйте: в базе хеши
  паролей и действующие токены входа (30 дней).
- Обновляйте зависимости и сам сервер; следите за `npm audit`.

## Что уже сделано в коде

- Пароли — только bcrypt (cost 10), сравнение без утечки по времени.
- Сессии — случайные токены в базе, срок 30 дней, отзыв при выходе и сбросе
  пароля.
- Ограничение попыток входа по IP и по нику, ограничение загрузок.
- Проверка origin для десктопных IPC-вызовов (в десктопной сборке, не в этом
  репозитории), `contextIsolation`, без `nodeIntegration`.
- Административные действия пишутся в журнал (последние 1000 записей).
